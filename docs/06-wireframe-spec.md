# 06 — Wireframe Specification

Wireframes are required before polished implementation.

## Fidelity

Create layout-first wireframes using grayscale/placeholder assets. The goal is hierarchy and composition, not final styling.

## Homepage wireframe

### H01 — Global header
- compact contact utility if retained
- logo
- navigation
- search
- quote CTA

### H02 — Hero
Must include:
- eyebrow/positioning
- H1
- concise support copy
- primary CTA
- secondary CTA if useful
- real/product/facility image area

### H03 — Product discovery
- section heading
- enough context to distinguish products
- product grid/carousel decision based on item count and mobile UX
- View All Products

Prefer grid on desktop unless carousel has a clear reason.

### H04 — Applications/solutions
Six current reference groups can inspire initial IA.
Use visual hierarchy distinct from product cards.

### H05 — Company story/trust
- legacy statement
- meaningful history/experience proof
- image composition
- About CTA

### H06 — Services preview
Include only if it strengthens the business journey and does not create homepage overload.

### H07 — Distributor/certification proof
- real logos
- relationship description where relevant
- avoid decorative logo dumping

### H08 — Quote CTA
Strong, simple conversion section.

### H09 — Footer
- company summary
- product links
- navigation
- contact
- social
- legal

## Product archive wireframe

1. Page intro/breadcrumb
2. Category/application discovery
3. Product grid
4. Optional filter/search
5. Quote/help CTA

## Product detail wireframe

### Above fold
Desktop:
```text
Breadcrumb
[Gallery / media] [Product title
                   short description
                   key attributes
                   primary CTA]
```

Mobile:
```text
Breadcrumb
Title
Gallery
Summary
Key attributes
CTA
```

### Body
- overview
- specs
- applications
- features
- downloads
- relevant services
- FAQ
- related products
- final CTA

Consider sticky in-page section navigation only if content length justifies it.

## Collection/application page wireframe

Long pages need hierarchy.

Suggested:
1. Hero/intro + brochure/quote
2. What this category means
3. Key advantages
4. Relevant products
5. Solution/use-case groups
6. Applications
7. Industries
8. Technical/selection table
9. How to choose
10. Comparison
11. supply/reach
12. FAQ
13. quote CTA

On desktop consider an optional table-of-contents/anchor rail for very long content.

## Services archive wireframe

- CTA

## Service detail wireframe

- breadcrumb
- title
- visual process gallery
- service summary
- capability/specification block
- applications

- CTA
- FAQ

## About wireframe

Do not use an ordinary repeated-card layout.

Suggested:
1. Intro/legacy hero
2. founder story
3. generational timeline
4. company evolution imagery
5. vision
6. mission
7. trust principles
8. company profile CTA
9. final contact CTA

## Contact wireframe

1. contact hero
2. sales/contact methods
3. locations grid/list
4. inquiry form
5. map
6. expectation note (response time only if verified)

## Responsive wireframe checkpoints

Create at least:
- 1440 desktop
- 1024 tablet landscape-ish
- 768 tablet
- 390 mobile

Do not derive mobile solely by stacking desktop components.
